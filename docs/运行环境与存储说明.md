# 运行环境与存储说明

## 1) 运行环境是不是 OpenAI 在亚马逊上的服务器？

在当前会话里，我**不能直接看到底层云厂商标识**（例如 AWS/GCP/Azure 的账户信息、实例元数据权限、控制台），因此不能把“OpenAI 使用亚马逊服务器”当作已验证事实。

更准确的说法是：你现在拿到的是一个托管的容器化执行环境，我可以读取该环境的实际磁盘配额与占用情况，并据此做容量管理建议。

## 2) 这个环境当前存储上限大概多少？

以仓库目录为观察点，`df -h .` 的结果显示：

- 总容量：约 **63G**
- 已用：约 **26G**
- 可用：约 **34G**

`df -i .` 显示 inode 也充足（约 383 万可用量级）。

> 因此，按当前体量判断，短期内不会因为磁盘容量立即阻断项目。

## 3) 会不会到达限制并导致项目停止？

有可能，但主要取决于数据留存策略：

- 只保留结构化中间结果与聚合报表：增长较慢；
- 长期保留大量原始文本快照/页面快照：增长较快，可能触顶。

建议采用：

1. 最近 30~90 天保留明细，历史转周/月聚合；
2. 按日分区存储并压缩（gzip/zstd）；
3. 设定 70%/85%/95% 容量阈值告警；
4. 明确“热数据（执行）/冷数据（归档）”分层。

## 4) 实操建议（面向本项目）

- 每次循环运行后仅保留必要 artifacts；
- 对 `workflow/input/` 的历史抓取样本做滚动归档；
- 在自动化任务中增加 `df/du` 监控步骤，提前触发清理或转储。
